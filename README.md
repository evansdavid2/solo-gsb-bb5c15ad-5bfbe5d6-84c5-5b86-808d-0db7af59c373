# 舞台换景排练台（Stage Change Cue Sheet）

供舞台监督在排练时记录与校验“换景”操作的网页应用：按唯一的**提示号（Cue No.）**录入一组
**同时发生**的道具转移，系统逐组校验来源与区位占用，整组通过才生效；任意提示插入、修改或
删除后，按提示号重放全部提示，展示每组结果与最终区位。

技术栈：Node.js + Express + SQLite（better-sqlite3）+ 原生 JavaScript（无前端构建）。

## 换景规则

- 区位分两类：
  - **后台**：内置、唯一，可容纳**任意数量**道具；
  - 其他区位（上场门、下场门、一桌二椅位等）：每个区位**只容纳一件**道具。
- 每件道具有唯一的**初始区位**（初始状态下，单件区位上至多一件道具）。
- 按唯一提示号录入一组同时发生的转移，组内：
  - 每件道具**最多转移一次**；
  - 每条转移都从**变动前状态**校验来源：道具当时必须确实位于来源区位；
  - 该组完成后，任一件数限制区位不得被多件道具占用；
  - 因此 **A、B 同组互换区位是允许的**（A→B 的位置、B→A 的位置）；
  - 任意一条不满足，**整组不生效**，并显示全部冲突原因。
- 插入、修改或删除任意提示后，从初始区位起**按提示号升序重放**全部提示：
  - 每组显示“整组生效 / 冲突 · 整组未生效”及转移明细或冲突原因；
  - 失败的提示组不改变状态，后续提示继续基于该状态重放；
  - 页面展示全部道具的**最终区位**。

## 一条命令启动（Docker Compose）

要求已安装 Docker（含 Compose 插件）。在项目根目录执行：

```bash
docker compose up --build -d
```

该命令一次完成：

1. 构建镜像并安装依赖（`npm install`）；
2. 启动容器时自动初始化 SQLite 数据库——建表、建索引、写入内置区位“后台”；
3. 在后台启动服务，数据持久化到宿主机 `./data/stage.db`。

启动后打开：

- **http://localhost:3000**

查看日志 / 停止：

```bash
docker compose logs -f
docker compose down          # 停止并删除容器（数据库文件保留在 ./data）
```

> 端口被占用时可改宿主机端口，例如用 8080：
>
> ```bash
> HOST_PORT=8080 docker compose up --build -d
> # 然后访问 http://localhost:8080
> ```

## 不用 Docker 的本地启动

需要 Node.js ≥ 20（推荐 22）。

```bash
npm install
npm start
```

同样打开 http://localhost:3000 ，数据库默认创建在 `./data/stage.db`。

## 配置（环境变量）

均为可选项，不配也能直接运行：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 服务监听端口（容器内）。 |
| `HOST_PORT` | `3000` | 仅 Compose 使用，宿主机映射端口（`HOST_PORT=8080 docker compose up`）。 |
| `DB_PATH` | 本地：`./data/stage.db`；镜像内：`/app/data/stage.db` | SQLite 数据库文件路径。 |

修改容器内监听端口时，需同步调整 `docker-compose.yml` 的端口映射。

## 网页地址与端口

- 默认地址：**http://localhost:3000**
- API 前缀：`/api`（页面与 API 同源，由 Express 直接托管 `public/` 静态文件）。

主要接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 基础数据 + 全部提示重放结果 + 初始/最终区位 |
| POST/PUT/DELETE | `/api/locations[/:id]` | 新增 / 改名 / 删除单件区位（后台不可删） |
| POST/PUT/DELETE | `/api/props[/:id]` | 新增 / 修改 / 删除道具（含初始区位） |
| POST | `/api/cues` | 录入一组转移（body：`cueNo, note, moves[]`） |
| PUT | `/api/cues/:cueNo` | 修改提示（可改提示号、转移明细；整组校验不过则回滚） |
| DELETE | `/api/cues/:cueNo` | 删除提示，删除后返回全量重放结果 |

转移对象格式：`{ "propId": 1, "fromLocationId": 2, "toLocationId": 3 }`。

## 使用流程建议

1. 在左栏添加所有单件区位（“后台”已内置）；
2. 添加道具并指定初始区位；
3. 在右栏按排练顺序录入提示：填提示号（如 1、2、3……）、逐条选择道具 / 来源 / 目标；
   选择道具后会自动带出其当前区位作为来源参考；
4. 提交后立即看到本组是否生效；修改或删除任意提示，所有提示会重新重放。
